## SQLite 资源库 + 帧缓存改造（完成）

- 用户诉求：减少近万个零散资源文件（png/ 403M + music/ 71M）的读取，询问 SQLite 方案可行性。
- 分析结论：SQLite 可行但最大性能问题是每帧重复 磁盘读+PNG解码+缩放，故缓存与 DB 一起做。
- 产出：
  - `tools/build_assets_db.py`：资源打包脚本 → `assets.db`（9820 条，459.5MB，14s），表 `assets(role,kind,name,category,data)`，语音分类 greeting/chat/know。
  - `resource_store.py`：`ResourceStore` 抽象层，SQLite 优先、文件系统回退。
  - `desktoppet.py`：帧/语音/BGM 全走字节流加载；换角色预加载预缩放全部帧（达达利亚 219 帧 0.5s 一次性成本），`act()` 纯内存切换；顺带修了托盘图标、BASE_DIR 重复拼接、死代码。
  - `tests/test_resource_store.py`：双后端一致性测试，pytest 4 passed。
- 发现：全库实际 28 个角色，与菜单一致；config.yaml 里有脏 key（万叶/心海 与目录名不符）；data/ 与 png/、music/ 重复约 500M（打包用副本）；greeting() 15~17 点无问候语——这些留待后续清理。
- assets.db 已加入 .gitignore（生成物）。

## 重写 setup.iss 安装脚本（完成）

- 问题：旧脚本无 AppId、装 Program Files 导致程序写 config.yaml/assets.db 权限失败、欢迎页 MsgBox 扰民。
- 新脚本：固定 AppId GUID（2B18A692-...）、版本 2.0、默认装 `%LOCALAPPDATA%\Programs\原神桌面宠物`（PrivilegesRequired=lowest）、仅 64 位、CloseApplications 支持覆盖安装、可选桌面图标/开机自启、lzma2/normal。
- 打包链路（已全链路实测通过）：`uv run --with pyinstaller pyinstaller desktoppet.py --name 原神桌面宠物 --onedir --noconsole --icon=src/icon256.ico --add-data "config.yaml;." --add-data "assets.db;." --add-data "src/icon256.ico;."` → dist 592M → `ISCC.exe setup.iss`（133s）→ `inno_build/原神桌面宠物安装向导.exe` 480M。静默安装到默认目录验证成功，文件可写。
- 教训：unins000.exe 静默卸载是异步的，会话结束时子进程会被回收导致卸载中断——需在同一会话内轮询等待。残留已清理。
- build/、dist/、inno_build/、*.spec 已加 .gitignore。
